## 推荐从哪里读

下列推荐是本站根据问题匹配度、实验可解释性和可复用机制作出的阅读判断，不是引用量排名。

| 想研究什么 | 优先阅读 | 具体值得看什么 | 需要一起读的限制 |
|---|---|---|---|
| 让成熟 coding harness 在效果与成本间取舍 | [HarnessPro](../?paper=2610.26770) | 从 Codex / Claude Code 出发，分析、计划、编辑、生成测试四种角色配合修改；保留效果与成本不同的候选 | 每篇实验的开发与正式测试分开；节省的是运行成本，不等于搜索阶段也便宜 |
| 同时更新模型参数与 harness | [Self-HPO](../?paper=2610.22791) | 在搜索 harness 和训练策略模型之间交替；比较自己提修改与外部模型修改 | 部分搜索与训练共用开发题；正式测试独立，不能把开发增益直接当迁移收益 |
| 把改进积累成可组合组件 | [PluginRSI](../?paper=2609.32423) | 把角色、工具、skill、memory 做成可复用插件，区分组件突变与重新组合 | 复用曲线的部分实验会继续优化先前留出题，与冻结后测试不是同一协议 |
| 先改评估器，避免 agent 被错误评分带偏 | [VeriEvolve](../?paper=2610.29005) | 用有挑战性的终态检查评估器，再据此搜索执行流程 | 外部 verifier 仍参与样本入组和漏判筛选；主要证据是同任务适应，不是完全无外部反馈 |
| 从持续产生的新任务中学 | [EvoForesight / DeepEvolve](../?paper=2610.29784) | 预测尚未发生的事件，结果发生后获得可核对答案；参数和 skills 使用不同反馈 | 时间隔离与信息缓存是关键条件；新闻数据仍需检查是否提前暴露结局 |
| 改进“负责改进的算法” | [RSI-Opt](../?paper=2610.32026) | 外层修改优化器 agent 的规则和代码，内层据此提出模型训练优化程序 | 部分迁移下降；等决策次数不等于等算力，缺少某些重置对照 |
| 判断论文是否真的证明递归改进 | [Auditing the Product, Not the Recursion](../?paper=2610.27610) | 把产物变好、选择过程与修改机制变好分开审计 | 属于有范围限制的文献编码，不能当作整个领域的质量排行榜 |
| 学习已进入大模型训练流程的机制 | [Thinking Machines OPD 博客](../?paper=tml-on-policy-distillation) | 学生生成轨迹，教师提供逐 token 分布监督；GLM / DeepSeek 报告明确采用这一类机制 | 固定教师蒸馏本身不等于递归自我改进；博客也明确建立在更早工作之上 |

每篇链接中的 TL;DR、五个直接展示的维度和折叠研究表，均附对应原文章节。原文未公布的角色型号或题数明确注明“未披露”，不补猜测。
